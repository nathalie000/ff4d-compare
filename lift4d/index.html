1 · Layout post-processing — before vs. after (slerp+smooth)

The per-frame SAM3D layout (object pose) jitters and flips on near-symmetric objects. Post-processing (no retraining): rotation ← slerp(first, last frame) — removes flips; translation / scale / per-frame compose corrections ← Savitzky-Golay smoothing (window 9) — removes pose noise while keeping real motion. Both columns rendered identically from the same checkpoint; only the layout track differs.

2 · ff4d-sam3d data prep — per-frame canonical 3D assets

Each video steps through 16 frames (2 fps) sampled across the clip. Per frame, 5 canonical views of: RAW gs — the Lift4D asset (deformed gaussians, rigid motion factored into the layout stream; the encoder INPUT) · OURS gs / mesh — SLat encode→decode · OURS occ — SS encode→decode (position-colored occupancy). Assets use the full deformation (node-base MLP baked via baked_dxyz) and the temporally-smoothed rigid decomposition.
